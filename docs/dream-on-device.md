# Relay · 端上做梦(知识固化)

> 状态:可行性论证(2026-08-17),不是实现 spec。
> 问题:端侧 3B 能不能支撑"做梦"式知识固化?为什么这活该在端不在云?
> 承接:记忆契约见 [memory-engine.md](./memory-engine.md);定位见 [vision.md](./vision.md)。

---

## 0. 结论先行

能,但前提是**你不能让 3B "做梦"**——得让它做几千个微小、有边界的判断。一句话:**3B 是视网膜,不是大脑皮层。** 全局的"想通了"不该由 3B 完成,该由图谱结构 + 代码 + 偶尔的云端完成。

---

## 1. 3B 能干和不能干的

| 能(小上下文、单点、结构化输出) | 不能(一上来就废) |
|---|---|
| 从**一段**对话抽三元组 | 把一周原始对话塞进窗口(直接爆) |
| 判断"这俩是不是同一实体"(成对二元) | 对**整张图**做全局抽象 |
| 把**一段**对话缩成几条要点 | 多跳推理、长链不漂移 |
| 判断"A 和 B 是否矛盾"(成对、短) | "这三件事其实是同一道理"这种 novel 洞察(幻觉重灾区) |
| 归一化、打标签、改写 | |

凡是"读一大堆、然后升华"的活,3B 都做不了;凡是"看一小段、吐个结构"的活,它都能做。**做梦要拆成后者。**

---

## 2. 让它在端上成立的三个杠杆

1. **把梦拆成微任务(永远小上下文)**:一次梦不是"想一整晚",是几千次"看一小段、吐一条边"。全局工作交给**图遍历和代码**(去重、传递闭包、矛盾=图约束冲突),3B 只在每个节点/边上做局部感知。这就是 orchestra 的 Pipeline / Call。
2. **约束解码,别让它自由发挥**:llama.cpp 有 **GBNF grammar**。做梦时强制 3B 只能吐合法三元组 JSON,不许自由作文。对小模型可靠性是**数量级**提升——现成能加的最狠一招。
3. **神经-符号分工 + 深睡上云**:
   - **感知**(模糊→结构):3B
   - **固化**(去重、连线、消矛盾、修剪):**代码 + 图**,不是 3B
   - **连线/去重**更该用一个**小 embedding 模型**算相似度,而不是 3B 成对判断(见 memory-engine §4)
   - **难的 1%**(真抽象、大重构):攒着,偶尔一次**深睡上云**

---

## 3. 反直觉的关键点:时间不是约束

梦在充电、空闲、夜里跑,你有几个小时。就算 3B 慢,一晚上几百个微任务绰绰有余(拿 `GenerateTimings` 的真实数字算)。

**真正的约束是"单次质量"和"上下文大小",这俩都用"拆小"解决,不用等更快的芯片。** 这反而是端侧优势:云端按 token 收费,不敢让它磨一晚上;端上磨一晚上是免费的。

---

## 4. 残余风险与兜底

- **3B 抽取仍有错**:每条边挂 confidence + provenance,错了可见、可回滚。
- **高风险结论**:进晨报让人确认 / 否决,别自动写死图谱。
- **模型变强了**:因为留了出处(原文在 ArtifactStore),可**重做梦**。

---

## 5. 为什么这活在端不在云

先接受挑战里对的半边:**论"单次能力",云端赢,没争议。** 别在能力这条轴上防守。真正的回答是**换轴**——做梦这件事的四个属性,条条偏端:

| # | 属性 | 为什么偏端 |
|---|---|---|
| 1 | **数据引力 / 隐私** | 做梦是**唯一要读全部原始语料**的步骤。单次问答上云 ≠ 授权把全量日记每晚吸走。scope 和连续性差一个量级。 |
| 2 | **成本 / 谁买单** | 云端做梦 = 每晚永远按 token 收费,而数据终身只增。等于给"整理你自己的笔记"按月收租。 |
| 3 | **空闲吞吐,不是抢时间** | 做梦没 deadline。给没 deadline 的活烧云端钱,是花最贵的即时性买最不需要的东西。 |
| 4 | **所有权 / 离线 / 活得久** | 固化在云端 = 第二大脑是租来的,断网/退订/厂商倒闭就没了。合规市场里原始语料依法不能出端。 |

### 5.1 主动认输——把挑战者对的收进来

架构里**本来就留了"深睡上云"**:端上做 99%(读全量、去重、连线,隐私重、无 deadline),把明确够不着的 **1% 硬抽象**蒸馏成脱敏 artifact 送云端。**挑战者对的那 1%,已经给云端了。** 分歧只在:他想把 99% 也搬上去,而那 99% 恰恰最不该走。

### 5.2 什么时候他完全对、就该全云端

用户无隐私顾虑 + 愿意持续付费 + B2B / 分析场景 + 现在就要最好的图。这种别端上硬撑,老实上云。

### 5.3 一句话给你被怼时用

> "不是端 vs 云,是**读全量的脏活留端上(隐私+免费+反正没 deadline),够不着的硬抽象上云**。把全量语料每晚吸上云去省一个没有 deadline 的活,是花最贵的钱买最不需要的即时性,还赔上隐私。"

---

## 6. 建议:端上放什么

| 放哪 | 干什么 |
|---|---|
| 3B(GBNF 约束) | 单段抽取、成对矛盾判断、单段摘要 |
| 小 embedder(建议提前) | 去重、连线的相似度 |
| 纯代码 + 图 | 所有"全局"操作 |
| 云端深睡(罕见) | 3B 够不着的抽象;晨报里"存疑"的批量重审 |

**单靠 3B 去"做梦"不行;把梦拆成"3B 当传感器 + 图当大脑 + 云端偶尔顾问"就完全跑得动,而且是端侧反而划算的那种活。**

先做"单学科知识图"最稳,别一上来做跨领域第二大脑。
