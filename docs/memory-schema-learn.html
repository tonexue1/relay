记忆引擎怎么存

引擎里没有模型。库是 Room + bundled SQLite（带 FTS5）。它只做确定性的事：收下原文、按字写入三元组、按名字找出邻居、把旧边从活图上拿掉。下面用表把这件事讲清楚。

1. 先建立图景

用户看见的是 chatbot。库里不是聊天记录本身，是一张个人图：点是人/物，线是闭集关系（allergic_to、likes、works_at…）。

所以存的时候拆成两层：

层存什么在哪
附件对话全文ArtifactStore（文件或内存），钥匙 = SHA-256
账本票、事实、点、线一个 SQLite，下面这七张表
核心一句：raw_event 是对话真相（只追加）；fact_log 是已采纳事实（只追加）；node/edge 是可丢掉再重建的活图。

2. 跟一句「我对花生过敏」

点下面每一步，看库里多了什么。这比先背字段有用。

3. 七张表怎么连

text_ref 和 raw_event_ids 不是数据库外键，是字符串钥匙。真正的外键味道在 edge.src/dst → node.id。

4. 原文：raw_event + 柜子

capture 做两件事：正文 put 进 ArtifactStore，库里插一条票。正文列不存在。

字段类型含义
idTEXT PK这条事件的 id，capture 的返回值
graph_idTEXT哪张图。assistant 或 novel:…。每条读写必带，禁止跨图 JOIN
tsINTEGER写入时间，毫秒
session_idTEXT会话，可空串
roleTEXTuser / assistant
text_refTEXT柜子钥匙 = 正文 SHA-256。同一段字只占一份附件
sourceTEXT来源，默认 chat
consumedINTEGER0 未抽，1 已抽。点抽取读的是 0；成功后再 markConsumed

过敏那句 capture 之后，大概是：

idroletext_refconsumed
e1usera3f2…0

柜子里：a3f2… → 「我对花生过敏」。此时 node / edge / fact_log 仍空。

5. 底账：fact_log

模型（或人手）抽出 (用户, allergic_to, 花生) 之后，ingest 先记一笔流水。图可以重建，这笔不因为 forget 消失。

字段类型含义
idTEXT PK日志行
graph_idTEXT哪张图
tsINTEGER这条日志写入时间
sTEXT主语，人名/物名，不是 node id
pTEXT谓语。必须在闭集里，否则进 errors，不写图
oTEXT宾语
confidenceREAL抽取有多有把握，默认约 0.7
raw_event_idsTEXTJSON 数组，根据哪些原文抽的
retractINTEGER1 = 结束一个旧事实，不是新插一条
valid_atINTEGER世界钟：现实里何时开始为真
invalid_atINTEGER 可空世界钟：何时不再为真。空 = 还有效
sporaw_event_ids
用户allergic_to花生["e1"]

6. 活图：node / edge / alias

node · 点

同一 graph_id 里，canonical_name 唯一。类型 day1：person | place | thing | pet | org | other。

字段类型含义
idTEXT PK节点 id。用户是 {graphId}:user
graph_idTEXT哪张图
typeTEXT粗分类
canonical_nameTEXT规范名：「用户」「花生」
idtypecanonical_name
assistant:userperson用户
n2thing花生

edge · 线（最重要）

幂等键是 (src, relation, dst)。同一条再来：升 confidence、补 provenance、刷新 updated_at，不插第二行。

字段类型含义
idTEXT PK边 id
graph_idTEXT哪张图
srcTEXT起点，node.id
dstTEXT终点，node.id
relationTEXT谓语，如 allergic_to
confidenceREAL置信
created_atINTEGER系统钟：图何时学会
expired_atINTEGER 可空系统钟：何时从活图拿掉
valid_atINTEGER世界钟：现实何时为真
invalid_atINTEGER 可空世界钟：现实何时结束
updated_atINTEGER上次改这条边
provenanceTEXTJSON，来自哪些 raw_event id
srcrelationdst人话
assistant:userallergic_ton2用户 过敏 花生

node_alias · 别名

做梦时 mergeNodes(keep=林晚, drop=林晚晚)：drop 的活边系统过期，缺的边接到 keep，并记别名。

字段含义
graph_id + alias联合主键。一个叫法在一张图里只指向一个人
node_id指向规范节点

7. edge 上的双时钟

query / facts 的时刻 at（默认现在）要四个条件都过，才算活边：

created_at ≤ at AND (expired_at 空或 > at)
AND valid_at ≤ at AND (invalid_at 空或 > at)

系统钟 · 图自己的记忆

created_at / expired_at。forget、审核拒绝、mergeNodes 只打过期。意思是：图把它拿掉了，不是「现实里没发生过」。

世界钟 · 现实里是否仍真

valid_at / invalid_at。retract、功能边替换（比如搬了家）会打失效。意思是：以前住上海，现在不住了。

没有 DELETE。rebuildFromFactLog 除外：它清空 node/edge，按日志重放。

8. 辅助：FTS 和审核篮

node_fts

SQLite FTS5 虚表，给 query("花生") 用。命中名字后再走一跳 edge。它不是知识，是目录。

字段含义
node_idUNINDEXED，回表用
graph_idUNINDEXED，回表用
canonical_name可搜
aliases可搜

所以 query("火锅") 只有图里真有「火锅」这个节点才会中。过敏要查「花生」，或 facts(p=allergic_to)。

pending_review

模型没把握时，边可以进篮。接受：只撤记录。拒绝：边打 expired_at。

字段含义
edge_id主键，对应那条边
reason / confidence为何进篮
s / p / o给人看的快照，避免再 JOIN

9. 接口对上哪张表

MemoryStore主要碰谁

unconsumed / markConsumedraw_event.consumed
ingestfact_log + node + edge（可能 pending_review）
querynode_fts → node → 活 edge
facts / neighborhood活 edge
recent系统钟上最近动过的 edge（含刚过期）
forget只打 edge.expired_at
mergeNodesedge 系统过期 + 可能新边 + node_alias
rebuildFromFactLog清空活图，重放 fact_log
pendingReview / resolveReviewpending_review ± expired_at
上云不由某张表触发。playground 里点「抽取」读 consumed=0 的原文；点「做梦」跑夜间 agent 做 merge。许可档（private / cloud_ok）已经拿掉了。
