## 0. 承重假设(塌了愿景就塌)

按依赖顺序捋,前面塌了后面不用验:

1. **3B+GBNF 能从真实对话抽出干净三元组** —— 地基。抽取是垃圾,图就是垃圾,复利变负。
2. **给 3B 注入检索到的记忆,回答真的变好** —— 价值命题本身。没增益,"越用越聪明"是假的。
3. **不靠 embedding,FTS5+图遍历的召回够用** —— 决定是不是偷偷被 embedding 卡住。
4. **一天的量一晚上真能梦完,不过热不掉电** —— 决定"端上免费做梦"这个定位前提。
5. **做梦可幂等重跑 / 能从日志重建图** —— 决定"重做梦""可溯源"是不是真的。
6. **能划清 3B 够不着、必须上云的那 1%** —— 决定"深睡上云"不是空话。

**1 或 2 挂了,回去改路线,别往下投。**

## 1. Spike 卡片

### Phase 0 — 原子能不能用(最便宜、最致命)

**S0 · GBNF 在 JNI build 里真的能约束解码**
- 问题:llama.cpp 的 grammar 有没有接到 JNI?约束后输出还有意义吗?
- 实验:挂一个三元组 JSON 语法,跑 20 段,看 ① 是否 100% schema 合法 ② 延迟涨多少。
- 阈值:合法率 100%,延迟 <2×。否则 S1 的可靠性方案要换。
- 成本:1 天。解锁:S1。

**S1 · 抽取质量(地基)**
- 问题:3B+GBNF 抽的三元组,precision / recall 到底多少?
- 实验:选 **30–50 段真实对话**,3B 抽取,人工打分。
- 阈值:**precision ≥70%**、**recall ≥50%**。precision <50% = 负复利,回去想(换稍大模型?模板化抽取?抽取上云?)。
- 成本:2–3 天。**第一个该做的 spike。**

### Phase 1 — 价值到底存不存在

**S2 · 记忆注入对 3B 是否真有增益(价值命题)**
- 问题:把检索到的事实塞进 2048 窗口,答得比不塞好吗?还是白吃 token?
- 实验:造 **20–30 道"必须记得某事实才能答对"** 的题,3B 跑「注入 vs 不注入」对照。
- 阈值:注入组**明显赢**(如 80% vs 20%)。无显著提升 = 命题破产。
- 成本:2 天。**和 S1 并列最高优先。**

**S3 · 无 embedding 的召回 + 去重够不够**
- 问题:FTS5+图遍历能否把对的记忆捞上来?同实体能否合并?
- 实验:种一个小图,跑 20 个真实措辞查询;再灌入改写过的重复实体测合并率。
- 阈值:top-k 命中 ≥70%;改写实体合并率 ≥60%。低于 50% = **embedding 从后置变前置**(重大发现)。
- 成本:2–3 天。

### Phase 2 — 手机上真跑得动吗

**S4 · 做梦吞吐 / 热 / 电(定位前提)**
- 问题:重度一天(如 30 段对话 → N 个微任务)在 Mate 70 上充电夜跑,多久?过热吗?
- 实验:真机、插电、跑完整做梦管线,用 `GenerateTimings` 量墙钟 + 测温 + 耗电。
- 阈值:**< 2–3 小时**完成,不触发热降频 / 熄火,充电不受影响。超了就砍任务量或分几晚增量做梦。
- 成本:2 天(依赖 S1 管线跑通)。

### Phase 3 — 设计正确性(便宜但趁早定形)

**S5 · 幂等重建**:同一份日志跑两遍做梦,断言不产生重复边 / 图收敛一致。阈值:两次结果等价。成本:1 天。

**S6 · 矛盾与时间**:事实变更时 `valid_from / valid_to`(或 supersedes)是否 hold,晨报能否正确挑出冲突。成本:1–2 天。

**S7 · 云端边界画线**:拿 S1 里 3B 失败的样本,看云端模型能否修好 → 定义"深睡"到底做什么。偏调研。成本:1 天。

**S8 · 端上工具调用可靠性**
- 实验:Qwen2.5-3B 跑「naive function-call」vs「GBNF 约束」vs「分类路由」,在 2 / 5 / 10 个工具下各测。
- 量:格式合法率、选对工具率、参数正确率,看**随工具数怎么衰减**。
- 阈值:定出"单步最多暴露几个工具还能 ≥90% 选对"——**直接决定 Pipeline 每步的工具预算**。
- 价值:不是 go/no-go,是标定必须把控制流从模型手里收回多少到代码里。
- 成本:1–2 天。

## 2. 一眼优先级(风险 × 便宜)

| Spike | 验什么 | 挂了意味着 | 序 |
|---|---|---|---|
| S1 抽取质量 | 地基 | 图=垃圾,项目重想 | **1** |
| S2 注入增益 | 价值命题 | "越用越聪明"是假的 | **1** |
| S0 GBNF | 抽取可靠性前提 | S1 变难 | 2 |
| S3 召回/去重 | 是否被 embedding 卡 | 路线图改 | 3 |
| S4 吞吐/热/电 | 定位前提 | "端上免费"不成立 | 4 |
| S8 工具可靠性 | 编排 vs 自主的边界 | 标定 Pipeline 工具预算 | 4 |
| S5/S6/S7 | 设计正确性 | 可边做边定 | 5 |

**节奏:S0+S1+S2 先打包做(约一周),这是 go / no-go 闸门——过了才值得往下投。S1 或 S2 不过,先别写任何 orchestra / memory 生产代码。**
