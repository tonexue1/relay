# Relay · 定位与记忆价值

> 状态:定位重写(2026-08-20,云端转向后)。给对外、招人、做取舍当尺子用。
> 变更:从"端优先=端上跑模型"改为"**端上是运行时+记忆+原生 UI,大脑(模型)在云**"。旧"端模型"版本见 git 历史。
> 主线:只做 **记忆 + 原生 UI**。隐私/脱敏/合规**暂缓**,不进当前主线(见 §5)。
> 范围:一句话定位、是/不是、给谁、楔子、记忆为什么值得做。
> 非目标:实现细节。记忆引擎见 [memory-engine.md](./memory-engine.md);UI 工具化见 [ui-kit.md](./ui-kit.md)。带"端侧 3B"的历史论证(dream / edge-tool-use)当结论留痕,不再是现行主线。

---

## 0. 一句话定位

**Relay 是一个 Android 原生的 Agent 运行时:agent 的运行时、私有记忆、原生 UI 都住在设备里,大脑(模型)放在云端。设备拥有"记忆 + 界面 + 编排",云只提供"这一次的智能"。**

对标不是 LangGraph / CrewAI(服务端 Python 框架),也不是又一个套壳 App,而是 **OkHttp / Coil 那种位置**——App 开发者 `implementation` 进去的基础库,只不过管的是 agent。

---

## 1. 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| Android 原生的 agent 运行时 / SDK | 一个终端用户 App、一个聊天机器人 |
| 设备拥有**运行时 + 记忆 + 原生 UI**,模型在云 | "纯端上跑个模型" 或 "纯云端 agent 平台" |
| 把端上**私有记忆当一等公民**(会复利的图谱) | 把记忆当成云端的附属缓存 |
| **UI 工具化**:模型产 spec,端上**原生**渲染进对话 | 把 UI 塞进 WebView / iframe |
| 分层库:`llm`→`agent-core`→`memory-api`→`ui-kit`→`orchestra`→`samples` | 一个大而全的黑盒 framework |

诚实边界:**模型能力我们不自己造,直接用云端最强的**——那条轴上跟云拼是输的仗。我们造的是**围着模型的那一圈:记忆、原生 UI、编排**,让"你的历史 / 界面 / 经验"沉淀在设备、活得比某一家模型久。端上推理(`ondevice`)降级为**可选加速**,不是定位前提。

---

## 2. 给谁用

Android App 开发者——想要 agent 能力,而且想要**会记事、越用越贴人**的体验 + **原生手感**:

- 陪伴 / 助理 / 第二大脑类消费应用
- 需要在对话里**展示图表 / 表格 / 卡片**、要原生手感而非网页嵌套的应用

(合规 / 隐私敏感场景不是当前目标客户,见 §5。)

---

## 3. 楔子(别人套壳云端抄不走的两点)

不是"能调个云端大模型"——谁都能。真正立得住的是两条:

1. **会复利的记忆**:别人做"一次推理",我们做**终身只增、能改能忘**的知识图谱,让云脑对你越来越对、越来越省 token。一致性 × 覆盖 > 峰值 IQ。抽取/蒸馏可以上云,图沉淀在端上你自己手里、跨模型可迁移。
2. **UI 工具化 + 原生渲染**:agent 要展示可视化时,调用封装好的 UI 工具,把 `spec` 送回端上**原生 Compose 渲染**进对话。`spec` 是中间语言、渲染在端、**LLM 无关可测**;不是让模型吐 HTML 塞 WebView。

---

## 4. 为什么做记忆(越用越聪明)

先钉死一句,免得自欺:**"越用越聪明"变聪明的是系统,不是那颗模型。** 模型权重一个字节都不改,变的是喂给它的**上下文质量**。

在这个前提下,记忆的价值分四个**递进**层次,越往下越是真复利:

| 层 | 聪明 = | 何时有 |
|---|---|---|
| **L1 召回 / 个性化** | 不重复、不跑题、贴着你的历史 | day 1 |
| **L2 连接 / 多跳** | 把两件你没连起来的事连起来(过敏 × 菜谱→警告) | 有图就有 |
| **L3 预计算 / 摊销** | 先蒸馏出结论,查询又快又省;抽取在云 | 蒸馏跑起来后 |
| **L4 启发式 / 程序性** | 不只记得你,还记得"怎么帮你才对"(采纳/纠正→反馈边) | 需要反馈信号,最难也最值 |

平铺日志只能"翻到",图能"连起来";硬理解(抽边)可以上云做完,查询取回的是结论不是原始记录再推一遍。L4 接的是"启发式学习":把 采纳/否决/纠正 当反馈边写回图,久了 agent 偏向对**你这个人**历史有效的策略——把"记忆"升级成"经验"。

### 4.1 飞轮

```
用 → 原始日志变多 → 云端抽干净边 → 图更浓
   → 检索更准 → 回答更好、更省 token → 更爱用 ↺
         └─(采纳/纠正)→ 反馈边 → 策略更对 ↺
```

### 4.2 记忆的经济学(强模型也需要它)

即便大脑是云端最强模型,没记忆也是**每次从零、贵、还忘事**。记忆把上下文压到"当下相关的那一点点",带来三样硬收益:**省 token / 降成本、降延迟、跨会话连续**。加上图沉淀在端上、跨模型可迁移——这是纯云端 agent 平台**给不了**的。**这不是附加功能,是这套定位能否成立的前提。**

### 4.3 让复利"被看见"

复利用户感觉不到等于没有。要有**晨报**("我昨晚学到/连起了这些")+ 对话中主动回忆("我记得你提过…")+ 记忆相关的**原生 UI 展示**(用 ui-kit 把"新学到的事"渲染出来)。"变聪明"的体感和真变聪明一样值钱。

### 4.4 承重墙:记忆也能让你越用越蠢

这不是自动向上的。搞砸就是**负复利**:

- 抽取/蒸馏写错事实 → 错误复利,越攒越歪
- 只进不忘 → 上下文污染,检索被垃圾淹没
- 图很大但检索不准 → 死重量

所以 **confidence / provenance / 衰减遗忘 / 晨报复核不是可选项,是承重墙。** 记忆系统成败,一半在"记",一半在"敢忘、能纠"。

---

## 5. 暂缓(不进当前主线)

- **隐私 / 脱敏 / 合规**:消费级"隐私"多是安慰贴纸;真需求在受监管的 B2B(医疗 / 企业 / 律所 / 数据出境),是**法律闸不是情绪**,而且窄。**等有真实合规客户开口再做**——那时 `ondevice` 可承担"脱敏网关 + 端上应答"的可选档位。**现在不投产、不进主线。**
- 端上推理做"记忆问答 / 做梦 / 抽取":同样暂缓(S1 已否端侧抽取)。`ondevice` 目前只当可选加速留着。

---

## 6. 一句话收尾

**Relay 卖的不是"更强的模型"——大脑租云端的;卖的是围着模型的那一圈:把"你的历史 + 什么管用"蒸馏成模型用得起的上下文(记忆),把结果原生渲染进对话(UI 工具化),让这一切住在设备、能纠错、活得比某一家模型久。模型没变,但系统对你越来越对。**
